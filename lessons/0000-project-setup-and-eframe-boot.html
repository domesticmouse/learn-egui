Lesson 0000: Bootstrapping Your Rust & eframe Project

Creating the Cargo workspace and native window shell that your PCB Reviewer code will inhabit

Before we write the layer-visibility toggles and 2D board viewport in Lesson 0001, that code needs a real, runnable Rust project to live in. In this lesson, you will learn how Cargo structures a Rust binary, how eframe and egui divide responsibilities, and how fn main() boots a native desktop window.

1. egui vs. eframe: Who Does What?

A common surprise for newcomers is that the egui crate itself does not open OS windows or talk directly to Metal, Vulkan, or OpenGL.Because egui only takes input events and outputs 2D triangles and textures, it can be embedded inside game engines, custom CAD renderers, or headless test runners.

  • egui (The UI Core): Computes widget layouts, processes pointer/keyboard state, and generates 2D vector shapes for a single frame.
  • eframe (The App Shell): The official framework wrapper (docs.rs/eframe) that creates a native desktop window (or WebAssembly canvas), initializes the GPU painter, and calls your app's update() method on every repaint.

2. Creating the Project & Configuring Cargo.toml

In Rust, cargo new pcb-reviewer generates a binary package with two key files: Cargo.toml (the manifest) and src/main.rs (the entry point).

Here is the complete Cargo.toml for our Schematic & PCB Reviewer:Tip: Single Dependency Import. Because eframe re-exports egui as eframe::egui, we only list eframe under [dependencies]. This guarantees your egui types never suffer a version mismatch with eframe. 

[package]
name = "pcb-reviewer"
version = "0.1.0"
edition = "2024"

[dependencies]
eframe = "0.33"

# Optimize dependencies (like egui/eframe) even in debug builds so our
# 2D PCB canvas renders at 60 FPS while keeping our own code fast to compile.
[profile.dev.package."*"]
opt-level = 2

That final three-line block (Cargo Profile Overrides) is essential for graphics and CAD tools in Rust: unoptimized debug builds (`opt-level = 0`) make software rasterizing and tessellation sluggish, whereas `opt-level = 2` on `package."*"` compiles third-party crates once at near-release speed while compiling your own `src/main.rs` edits in sub-seconds.

3. Anatomy of src/main.rs

Now let's look at the complete, runnable src/main.rs that hosts our PcbReviewerApp struct:In Rust, Result<T, E> represents an operation that either succeeds (Ok(T)) or fails (Err(E)). eframe::Result is a type alias for Result<(), eframe::Error>. 

use eframe::egui;

fn main() -> eframe::Result {
    let mut options = eframe::NativeOptions::default();
    options.viewport = egui::ViewportBuilder::default()
        .with_inner_size([1024.0, 720.0]);

    eframe::run_native(
        "Schematic & PCB Design Reviewer",
        options,
        Box::new(|_cc| Ok(Box::new(PcbReviewerApp::default()))),
    )
}

pub struct PcbReviewerApp {
    pub show_top_copper: bool,
    pub show_bottom_copper: bool,
    pub show_silkscreen: bool,
    pub show_ratsnest: bool,
}

impl Default for PcbReviewerApp {
    fn default() -> Self {
        let mut app = Self {
            show_top_copper: false,
            show_bottom_copper: false,
            show_silkscreen: false,
            show_ratsnest: false,
        };
        app.reset_layers();
        app
    }
}

impl PcbReviewerApp {
    pub fn reset_layers(&mut self) {
        self.show_top_copper = true;
        self.show_bottom_copper = true;
        self.show_silkscreen = true;
        self.show_ratsnest = false;
    }
}

impl eframe::App for PcbReviewerApp {
    fn update(&mut self, ctx: &egui::Context, _frame: &mut eframe::Frame) {
        // Lesson 0001's SidePanel and CentralPanel code lives right here!
        egui::CentralPanel::default().show(ctx, |ui| {
            ui.heading("PCB Viewport Ready");
        });
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn default_enables_physical_layers_and_hides_ratsnest() {
        let app = PcbReviewerApp::default();
        assert!(app.show_top_copper);
        assert!(app.show_bottom_copper);
        assert!(app.show_silkscreen);
        assert!(!app.show_ratsnest);
    }
}

Three Rust Details Worth Unpacking

  1. Builder Pattern on ViewportBuilder: When configuring eframe::NativeOptions::default(), we customize options.viewport with egui::ViewportBuilder::default().with_inner_size([1024.0, 720.0]) to request a 1024×720 logical-point window while keeping all other window options at their defaults.
  2. Custom impl Default Delegating to reset_layers(&mut self): Rust lets you annotate a struct with #[derive(Default)], which sets every bool field to false. Because an engineer opening a PCB wants copper and silkscreen visible immediately (`true`), we write an explicit impl Default for PcbReviewerApp block that calls app.reset_layers(). Putting the layer initialization in a dedicated reset_layers(&mut self) method also allows cargo-mutants (which skips impl Default blocks directly to avoid infinite recursion) to mutate and verify our initialization logic.
  3. The App Creator Closure (Box::new(|_cc| Ok(Box::new(...)))): eframe::run_native takes a factory closure that runs once after the GPU context (`_cc: &CreationContext`) is ready, allocating your PcbReviewerApp on the heap (Box::new) and handing ownership to eframe.

4. Continuous Verification & Mutation Testing from Day 1

Across every lesson in this course, we don't just run the window—we prove our logic is tested with cargo test and monitor our assertion coverage using cargo-mutants (Testing & Mutation Cheat Sheet).Why mutation testing? Standard line coverage only checks whether a line of code ran during a test. cargo-mutants deliberately hollows out method bodies or flips operators/booleans in your code and verifies that cargo test actually fails (a Caught Mutant) rather than silently passing (a Missed Mutant).

Look at the #[cfg(test)] mod tests block at the bottom of src/main.rs above. The attribute #[cfg(test)] tells rustc to compile that module only when you run cargo test (Rust Book §11.1). When cargo-mutants replaces the body of PcbReviewerApp::reset_layers with an empty no-op (), assert!(app.show_top_copper) immediately fails and catches the mutant.

Installing cargo-mutants

cargo-mutants is a third-party Cargo subcommand that works directly with standard, stable Rust (no nightly toolchain required). Install it once globally with cargo install, then verify it is available on your PATH: 

# Install the cargo-mutants subcommand once (takes ~30s to compile)
cargo install --locked cargo-mutants

# Verify the subcommand is installed
cargo mutants --version

To configure cargo-mutants so it mutates our application state logic without trying to launch the blocking OS window in fn main(), add a .cargo/mutants.toml file to your project: 

# .cargo/mutants.toml
# Reuse the target directory across scratch builds so mutation runs finish quickly.
copy_target = true

# Skip the OS window launcher and raw panel draw loop until Lesson 0006
# introduces headless UI testing with egui_kittest.
exclude_re = [
    "replace main",
    "<impl eframe::App for PcbReviewerApp>::update",
]
