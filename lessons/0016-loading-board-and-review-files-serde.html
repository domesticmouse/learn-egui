0016. Loading & Saving Board & Review Session Files (serde, serde_json & thiserror)

Serializing BoardModel and ReviewNote pins into a schema-versioned ReviewSessionEnvelope JSON payload, validating untrusted inputs with exhaustive destructuring, and surfacing SessionIoError banners in egui::Panel::right without panicking.

Versioned Envelope Persistence and Exhaustive Destructuring

A hardware design review tool is only useful if engineers can save their review pins (ReviewNote status, severity, author, and millimetre coordinates) to a file, share it in a pull request, and reload it without losing state.Why Wrap BoardModel in ReviewSessionEnvelope? Serializing a raw BoardModel directly leaves no metadata to detect format changes later. Wrapping it in ReviewSessionEnvelope { schema_version: 1, board_id, board } lets from_session_json reject incompatible schema versions with a clear, typed error before touching application state.

Because pcb-doc (L1) owns all domain types, adding persistence requires zero changes to our egui rendering code:

  1. Enable emath's "serde" feature: In crates/pcb-doc/Cargo.toml, emath = { version = "0.37", features = ["serde"] } enables Serialize and Deserialize on Pos2, Vec2, and Rect.
  2. Define a typed SessionIoError with thiserror: Instead of returning opaque strings or panicking on corrupt files, SessionIoError models three explicit failure modes: EmptyBoardId, UnsupportedSchemaVersion { found, expected }, and MalformedJson(String).
  3. Destructure ReviewSessionEnvelope exhaustively: In BoardModel::from_session_json, we unpack let ReviewSessionEnvelope { schema_version, board_id, board } = ... without .. so adding any new envelope field in the future triggers a compiler error until validation is wired.

Non-Destructive Error Recovery in egui::Panel::right

When a user attempts to load a corrupt or incompatible JSON file in PcbReviewerApp::import_session_from_json(&mut self, raw: &str), the UI must never overwrite self.board with partial data or crash.Why Panel::right("session_panel")? Placing session persistence, snapshot controls, and error banners in a dedicated right-hand inspector panel keeps the left layer/BOM panel (Panel::left) and top cross-probe bar (Panel::top) within their vertical and horizontal layout budgets. On Err(err), import_session_from_json leaves self.board untouched, stores Some(err.to_string()) in self.view.last_io_error, and renders a dismissible "I/O Error: ..." banner inside Panel::right("session_panel").
