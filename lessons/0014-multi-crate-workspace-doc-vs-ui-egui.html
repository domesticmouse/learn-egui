0014. Multi-Crate Workspace: Separating pcb-doc (L1) from pcb-reviewer (L6)

Splitting domain geometry, DRC math, and review pin invariants into a pure, headless pcb-doc library crate (L1 depending only on emath) so cargo test -p pcb-doc and cargo mutants -p pcb-doc execute in milliseconds without linking egui or eframe.

Why Engine-First egui Apps Split Domain State into L1 Crates

In Lessons 0000 through 0013, our BoardModel (traces, pads, components, review_pins, and DRC clearance math) lived in the same src/main.rs binary crate as ViewState and PcbReviewerApp. That kept early lessons compact, but every single edit to a pure domain function—like pad_edge_gap_mm or ReviewStatus::can_transition_to—forced rustc and cargo-mutants to re-link the entire eframe + egui + windowing stack.Strict L0–L7 Layering: Production egui CAD and graphics workspaces organize crates into a strict directed acyclic graph (DAG): L0 foundational math (emath), L1 pure document model (pcb-doc), L2–L5 file formats and command engines, L6 reusable egui widgets/panels, and L7 native/Wasm shell binaries.

By refactoring ./apps/0014-multi-crate-workspace-doc-vs-ui-egui into a Cargo [workspace] with two crates:

  1. crates/pcb-doc (L1 Domain Crate): Depends only on emath = "0.33" for Pos2, Vec2, and Rect. It contains zero egui, eframe, winit, or Color32 types. For layer colors, PcbLayer::rgb(self) -> (u8, u8, u8) returns a UI-agnostic RGB tuple that pcb-reviewer bridges into egui::Color32.
  2. pcb-reviewer (L6/L7 UI Crate): Depends on pcb-doc = { path = "crates/pcb-doc" }, eframe = "0.33", and egui_kittest = "0.33". It owns ViewState, BoardViewport, LayerSwatch<'a>, and the eframe::App shell.

Enforcing Layer Boundaries and Panic-Free Domain Code

A multi-crate workspace only stays clean if upward dependency leaks are caught automatically.Tier 1 Static & Manifest Gates: Checking include_str!("../Cargo.toml") inside a unit test—or running an xtask workspace auditor—prevents an accidental cargo add egui inside crates/pcb-doc from silently coupling domain logic to UI rendering. In crates/pcb-doc/src/lib.rs, we enforce two compile-time and Tier 1 invariants:

  • Panic-Free / Unsafe-Free Lints: #![forbid(unsafe_code)] and #![deny(clippy::unwrap_used, clippy::expect_used, clippy::panic)] at the top of lib.rs and main.rs guarantee that domain queries never crash the host process. Test modules opt in explicitly with #[cfg(test)] #[allow(clippy::unwrap_used, ...)].
  • Tier 1 Manifest Gate (validate_l1_manifest_no_ui_deps): Scans crates/pcb-doc/Cargo.toml against FORBIDDEN_UI_DEPS_BELOW_L6 (&["egui", "eframe", "winit", "egui_kittest", "rfd"]) and fails immediately if any UI crate is present.
