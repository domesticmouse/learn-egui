0017. Copy-on-Write Document Snapshots with Arc & Arc::make_mut

Wrapping BoardModel collections in Arc<Vec<T>> and Arc<HashMap<K, V>> (serde rc feature) so taking a snapshot is O(1), mutating a review pin clones only the touched HashMap, and proptest verifies structural pointer sharing (Arc::ptr_eq).

Why O(N) Deep Clones Break 60 FPS Immediate-Mode CAD Apps

Suppose a production PCB layout holds 50,000 TraceSegments, 20,000 SmdPads, and 2,000 ComponentSymbols, while an engineer adds or edits a single ReviewNote pin. If BoardModel stores plain Vec<T> and HashMap<K, V> fields, calling let snapshot = self.board.clone() before an edit allocates and copies every trace, pad, and component on the heap (O(N) memory and CPU time).Structural Sharing (Arc Copy-on-Write): By wrapping each collection in Arc<...> (Arc<Vec<TraceSegment>>, Arc<Vec<SmdPad>>, Arc<Vec<ComponentSymbol>>, Arc<HashMap<PinId, ReviewNote>>), BoardModel::clone() copies only four 8-byte pointers and increments four atomic reference counts (O(1)).

When we need to mutate a collection—such as inserting or updating a review pin—we call Arc::make_mut(&mut self.review_pins):

  • If strong_count == 1 (no snapshot shares this buffer): Arc::make_mut returns a &mut HashMap<PinId, ReviewNote> in-place with zero allocation.
  • If strong_count > 1 (a snapshot or undo entry shares this buffer): Arc::make_mut clones only review_pins into a new Arc allocation and mutates the new copy, while traces, pads, and components remain 100% pointer-shared (Arc::ptr_eq == true) with the snapshot!

Serializing Arc<T> with serde's "rc" Feature & Property Testing with proptest

To keep BoardModel's #[derive(Serialize, Deserialize)] working seamlessly across Arc<...> fields, we enable serde's "rc" feature and add proptest under [dev-dependencies] using cargo add:Tier 2 Property-Based Testing (proptest): Unit tests check fixed examples; proptest! generates hundreds of randomized (x, y, comment) inputs and shrinks any failure to its minimal counterexample.

Complete shared_arc_buffers, clear_review_pins, and transition_pin_status on BoardModel so mutations clone only the touched Arc buffer when shared.

pub fn shared_arc_buffers(&self, other: &Self) -> usize {
    usize::from(Arc::)
        + usize::from(Arc::ptr_eq(&self.pads, &other.pads))
        + usize::from(Arc::ptr_eq(&self.components, &other.components))
        + usize::from(Arc::ptr_eq(&self.review_pins, &other.review_pins))
}

pub fn clear_review_pins(&mut self) {
    Arc::.clear();
}

pub fn transition_pin_status(&mut self, id: PinId, next: ReviewStatus) -> bool {
    let Some(pin) = Arc::.get_mut(&id) else {
        return false;
    };
    if pin.status.can_transition_to(next) {
        pin.status = next;
        true
    } else {
        false
    }
}
