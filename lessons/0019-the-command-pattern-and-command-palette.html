0019. The Command Pattern, CommandSpec Registry & panic_hunt Fuzzer

Routing UI buttons, hotkeys, and a searchable Key::K Command Palette through a static COMMAND_SPECS registry in pcb-doc, enforcing EnabledFn preconditions, and fuzzing every registered command against adversarial JSON inputs (panic_hunt).

Why Engine-First egui Apps Route Actions Through CommandSpec

As an egui CAD application grows, scattering state mutations across dozens of if ui.button(...).clicked() closures makes it hard to keep menu items, keyboard shortcuts, command palettes, and CLI/automation scripts in sync.The Three-Tier Command Taxonomy (egui-command-engine): In an engine-first architecture, state-mutating operations and read-only queries live in a static CommandSpec table (COMMAND_SPECS), while shell/view toggles (Key::K palette modal, viewport pan/zoom) delegate to BoardModel::execute_command.

By defining a static COMMAND_SPECS: &[CommandSpec] registry inside crates/pcb-doc (L1), every command declares:

  1. Identity & Discoverability (id, label, shortcut, journal): Canonical dotted IDs ("review.addPin", "review.clearPins", "history.undo", "session.inspect") searchable by filter_command_specs(query).
  2. Informative Precondition Guard (enabled: EnabledFn): A plain function pointer fn(&BoardModel, &BoardHistory) -> Result<(), String> returning why a command is unavailable (e.g., "board has no review pins to clear" or "undo stack is empty"), which surfaces as EngineError::DisabledCommand.
  3. Validated Execution (run: RunFn): A function pointer fn(&mut BoardModel, &mut BoardHistory, &serde_json::Value) -> Result<serde_json::Value, EngineError> that validates untrusted JSON parameters (0.0..=100.0, non-empty comments) before mutating state or recording an undo entry.

Tier 5 panic_hunt Fuzzing & COMMAND_PARITY_FLOOR

Because CommandSpec::run accepts dynamic &serde_json::Value payloads (which can originate from a UI dialog, a CLI flag, or an MCP automation client), it must never panic when handed null, negative coordinates, out-of-bounds numbers, or whitespace-only strings.Ratchets Only Move Up (COMMAND_PARITY_FLOOR): Asserting COMMAND_SPECS.len() >= COMMAND_PARITY_FLOOR ensures that refactoring command modules never silently drops a registered command from the palette.

    if board.review_pins. {
        Err("board has no review pins to clear".to_owned())
    } else {
        Ok(())
    }

pub fn execute_command(
    &mut self,
    history: &mut BoardHistory,
    id: &str,
    params: &serde_json::Value,
) -> Result<serde_json::Value, EngineError> {
    let spec =
        .ok_or_else(|| EngineError::UnknownCommand(id.to_owned()))?;
    (spec.enabled)(self, history).map_err(|reason| EngineError::DisabledCommand {
        id: spec.id.to_owned(),
        reason,
    })?;
    
}
