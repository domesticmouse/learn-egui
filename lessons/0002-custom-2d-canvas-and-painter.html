Lesson 0002: Custom 2D Canvas & egui::Painter

Turning the empty CentralPanel into a multi-layer PCB viewport with Pos2, Vec2, Rect, and Copy semantics

In Lesson 0001, our CentralPanel only printed placeholder text labels ("Rendering Top Copper...") when a layer checkbox was toggled. Now we begin Act I: The 2D CAD Canvas & Viewport by replacing those text placeholders with an actual 2D vector canvas that draws an FR4 PCB substrate, Top and Bottom Copper traces, rectangular SMD pads, plated through-hole vias, Silkscreen courtyards, and unrouted Ratsnest airwires.

1. Reserving Canvas Space with ui.allocate_painter

Unlike standard widgets (ui.checkbox, ui.button) that compute their own size, a 2D CAD viewport needs you to explicitly tell egui how much rectangle space to claim and what mouse interactions to listen for.See Ui::allocate_painter in the official egui docs: it returns a two-element Rust tuple (Response, Painter) clipped to the allocated rectangle. 

egui::CentralPanel::default().show(ctx, |ui| {
    let (response, painter) =
        ui.allocate_painter(ui.available_size(), egui::Sense::hover());
    self.paint_static_board(&painter, response.rect);
});

Look at what happens in that single call:

  • ui.available_size() queries the remaining width and height inside CentralPanel as an egui::Vec2.
  • (response, painter) destructures the returned tuple: response.rect is the screen-space egui::Rect reserved for our canvas, and painter (egui::Painter) emits 2D vector primitives clipped to that rectangle.

2. Screen-Space Primitives & Rust's Copy Trait

In egui, screen coordinates are measured in logical points from the top-left corner of the window ((0.0, 0.0)), where +x points right and +y points down. Five lightweight types power all 2D CAD drawing:In Rust (Rust Book §4.1), small stack-only types like Pos2 (8 bytes), Vec2 (8 bytes), Rect (16 bytes), Color32 (4 bytes), and Stroke (8 bytes) implement the Copy trait. Passing f_cu_stroke into three painter.line_segment(...) calls copies 8 bytes on the stack each time—ownership never moves!

  1. Position (Pos2 / pos2(x, y)): A specific 2D coordinate point (e.g. a via center or pad center). Adding a displacement vector to a point yields a new point: origin + vec2(80.0, 90.0).
  2. Displacement / Size (Vec2 / vec2(w, h)): A 2D offset or width/height pair (e.g. vec2(20.0, 12.0) for an SMD pad's dimensions).
  3. Bounding Box (Rect): Defined by its top-left min: Pos2 and bottom-right max: Pos2 corners.
  4. Color & Outline (Color32 & Stroke): Color32::from_rgb(r, g, b) specifies a color, and Stroke::new(width_f32, color) bundles line thickness and color for traces and component outlines.

3. Extracting Pure Geometry Functions for cargo mutants

If you bury all coordinate math directly inside paint_static_board, you cannot unit-test your pad or board bounds without spinning up a full UI frame. Instead, extract pure geometry helpers that take Copy inputs (`Rect`, `Pos2`, `Vec2`) and return a `Rect`:Notice why we write Stroke::new(5.0_f32, ...) with an explicit _f32 suffix: Stroke::new accepts generic impl Into<f32>, and Rust 1.97+ warns if an untyped float literal falls back to f32 through a generic trait bound. 

/// Computes the inset FR4 board outline `Rect` inside the allocated `canvas_rect`
/// by shrinking all four edges inward by `margin` screen points.
pub fn centered_board_rect(canvas_rect: Rect, margin: f32) -> Rect {
    Rect::from_min_max(
        pos2(canvas_rect.min.x + margin, canvas_rect.min.y + margin),
        pos2(canvas_rect.max.x - margin, canvas_rect.max.y - margin),
    )
}

/// Computes the bounding `Rect` for a rectangular SMD pad centered at `center`
/// with width `size.x` and height `size.y`.
pub fn smd_pad_rect(center: Pos2, size: Vec2) -> Rect {
    let half_w = size.x / 2.0;
    let half_h = size.y / 2.0;
    Rect::from_min_max(
        pos2(center.x - half_w, center.y - half_h),
        pos2(center.x + half_w, center.y + half_h),
    )
}

Interactive Lab 3: Catching Arithmetic Sign & Factor Mutants cargo test + cargo mutants

When cargo mutants inspects centered_board_rect and smd_pad_rect, it systematically mutates every + to - and *, every - to + and /, and every / to * and % (25 total mutants across the file!). Notice why our test uses non-zero, asymmetric coordinates like pos2(100.0, 60.0) and vec2(16.0, 10.0)—if you tested at pos2(0.0, 0.0), then 0.0 - half_w mutated to 0.0 / half_w would both evaluate to 0.0 when half_w == 0.0! 

#[test]
fn centered_board_rect_insets_all_four_edges_by_margin() {
    let canvas = Rect::from_min_max(pos2(10.0, 20.0), pos2(310.0, 220.0));
    let board = centered_board_rect(canvas, 25.0);

    assert_eq!(board.min, pos2(35.0, 45.0));
    assert_eq!(board.max, pos2(285.0, 195.0));
}

#[test]
fn smd_pad_rect_computes_symmetric_bounds_around_center() {
    let pad = smd_pad_rect(pos2(100.0, 60.0), vec2(16.0, 10.0));

    assert_eq!(pad.min, pos2(92.0, 55.0));
    assert_eq!(pad.max, pos2(108.0, 65.0));
}
