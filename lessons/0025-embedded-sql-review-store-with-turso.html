Validating SQLite/Turso DDL and DML statements (CREATE TABLE, INSERT INTO, SELECT) with turso_parser::parser::Parser, enforcing idempotent schema migrations and foreign-key board constraints in TursoReviewStore, and bridging async #[tokio::test] storage into egui.

Why Engineering Design Reviews Need an Embedded Relational Store

JSON session files (Lesson 0016) are great for single-file snapshots, but multi-engineer hardware reviews require relational integrity: every anchored review thread (review_threads) must reference a registered PCB revision (boards), enforce idempotent schema migrations (CREATE TABLE IF NOT EXISTS ...), and support fast multi-column queries across authors, statuses, and severities.Why turso_parser + Embedded Relational Tables? Using Turso's official Rust SQL parser (turso_parser::parser::Parser) lets us parse and verify real SQLite/Turso SQL syntax (Stmt::CreateTable, Stmt::Insert, Stmt::Select) into strongly typed AST nodes (turso_parser::ast::Cmd) in pure Rust—compiling in 5 seconds, running on wasm32-unknown-unknown, and executing deterministically under cargo-mutants.

pub fn validate_turso_sql(sql: &str) -> Result<usize, SqlStoreError> {
    let trimmed = sql.trim();
    if trimmed.is_empty() {
        return Err(SqlStoreError::);
    }
    let mut parser = TursoSqlParser::new(trimmed.as_bytes());
    let mut stmt_count = 0;
    while let Some(cmd) = parser
        .
        .map_err(|e| SqlStoreError::InvalidSql(e.to_string()))?
    {
        if matches!(cmd, Cmd::Stmt(_)) {
            stmt_count += 1;
        }
    }
    Ok(stmt_count)
}
