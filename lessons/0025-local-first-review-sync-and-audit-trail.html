All-or-Nothing Sign-Off Transactions & Tamper-Evident Audit Trails

When a lead hardware engineer signs off a batch of resolved review pins before Gerber tape-out, partial updates are dangerous: if 2 of 3 pins transition cleanly (Resolved -> Verified) but the 3rd pin is still Open (an illegal Open -> Verified jump), the database must roll back the entire batch so the review store and its compliance audit log never diverge.Local-First Embedded Replicas & Hash-Chained Audit Logs: Each AuditLogEntry commits prev_hash: u64 into compute_audit_entry_hash(seq, pin_id, from_status, to_status, prev_hash). pub async fn sync_with_remote_replica(
    &mut self,
    remote_rows: &[SqlReviewRecord],
) -> Result<usize, SqlStoreError> {
    if !self.is_migrated() {
        return Err(SqlStoreError::NotMigrated);
    }
    let mut merged = 0;
    for remote in remote_rows {
        let should_accept = match self.rows.get(&remote.pin_id) {
            Some(local) => remote.revision ,
            None => true,
        };
        if should_accept {
            self.rows.insert(remote.pin_id, remote.clone());
            merged += 1;
        }
    }
    self.pending_local_writes = 0;
    Ok(merged)
}
