Lesson 0007: Split Viewports, egui::Scene & Borrow-Checker State Splits

Cross-probing from a Schematic Symbol Bar into the 2D PCB camera using TopBottomPanel, egui::Scene, and disjoint struct borrowing (&BoardModel + &mut ViewState)

When you are debugging a real hardware board, you almost always have two synchronised views open side by side: a Schematic View showing logical symbols and a PCB Layout View showing physical footprints. Click U1 in the schematic, and you want the PCB viewport to immediately highlight U1's electrical net and pan the PCB camera straight to U1's physical coordinates.

In Lesson 0006, we added reference designators (U1, R12, J1) and verified our UI panels headlessly with egui_kittest::Harness. Now, let's build that schematic-to-PCB cross-prober—and solve one of the most classic Rust borrow-checker puzzles you will hit in egui along the way.

Figure 7.1: Splitting immutable domain data (BoardModel) from mutable camera state (ViewState) allows simultaneous shared + mutable borrows across split viewports.

1. Just-in-Time Rust: Disjoint Field Borrowing (&BoardModel vs. &mut ViewState)

Suppose you iterate over self.components to draw a row of schematic symbol buttons, and inside that loop you call a &mut self method to recentre the camera:Which leads to a nice architectural bonus: separating read-only domain data from mutable UI/camera state prepares our code for Act IV (Lesson 0014), where BoardModel moves into its own standalone pcb-doc crate!

// ❌ COMPILER ERROR: cannot borrow `*self` as mutable because `self.components` is borrowed as immutable!
for comp in &self.components {
    if ui.button(&comp.ref_des).clicked() {
        self.focus_on_component(&comp.ref_des); // Borrows all of `&mut self`!
    }
}

If you have written Rust for more than ten minutes, you have probably met that exact error (E0502).

Turns out, Rust's borrow checker is smarter than it looks at first glance: it tracks borrows at the individual struct field level. When we group our read-only board data into pub board: BoardModel and our mutable UI/camera state into pub view: ViewState, rustc can see that &self.board and &mut self.view are completely disjoint in memory!

pub struct BoardModel {
    pub traces: Vec<TraceSegment>,
    pub pads: Vec<SmdPad>,
    pub components: Vec<ComponentSymbol>,
}

pub struct ViewState {
    pub selected_component: Option<String>,
    pub selected_net: Option<NetId>,
    pub hovered_net: Option<NetId>,
    pub pcb_scene_rect: Rect,
    pub viewport: BoardViewport,
}

impl ViewState {
    /// Reads `&BoardModel` immutably while mutating `&mut self` (`ViewState`)!
    pub fn focus_component(&mut self, board: &BoardModel, ref_des: &str) -> bool {
        if let Some(comp) = board.find_component(ref_des) {
            self.selected_component = Some(comp.ref_des.clone());
            self.selected_net = Some(comp.primary_net);
            self.pcb_scene_rect = Rect::from_center_size(comp.center_mm, vec2(40.0, 30.0));
            true
        } else {
            false
        }
    }
}

2. Multi-Panel Layouts with TopBottomPanel & egui::Scene

Alongside our custom TSTransform canvas from Lesson 0003, egui also ships a built-in pan-and-zoom container called egui::Scene. You pass &mut self.view.pcb_scene_rect into Scene::new().show(...), and Scene automatically updates that Rect whenever the user drags or scrolls—or whenever our schematic cross-probe overwrites pcb_scene_rect to jump the camera straight to a component:

egui::TopBottomPanel::top("schematic_cross_probe_bar").show(ctx, |ui| {
    ui.horizontal(|ui| {
        ui.label("Schematic Symbols (Click to Cross-Probe):");
        for comp in &self.board.components {
            let btn_label = format!("Probe {} ({})", comp.ref_des, comp.value);
            if ui.button(btn_label).clicked() {
                self.view.focus_component(&self.board, &comp.ref_des);
            }
        }
    });
});

Interactive Lab 3: Verifying Cross-Probe Camera Synchronisation in egui_kittest cargo test + cargo mutants

In apps/0007-split-viewports-and-egui-scene, our headless egui_kittest test clicks "Probe R12 (10k)" in the top schematic bar and asserts that harness.state().view.pcb_scene_rect.center() jumps to pos2(52.0, 35.0) and selected_net updates to Some(NetId(2)). If cargo mutants deletes the button handler or replaces focus_component with true or false, the test fails immediately!

#[test]
fn clicking_schematic_probe_button_updates_pcb_camera_rect_and_net() {
    let mut harness = Harness::new_eframe(|_cc| PcbReviewerApp::default());

    harness.get_by_label("Probe R12 (10k)").click();
    harness.run();

    assert_eq!(
        harness.state().view.selected_component.as_deref(),
        Some("R12")
    );
    assert_eq!(harness.state().view.selected_net, Some(NetId(2)));
    assert_eq!(
        harness.state().view.pcb_scene_rect.center(),
        pos2(52.0, 35.0)
    );
}
