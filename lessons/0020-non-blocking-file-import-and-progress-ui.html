0020. Non-Blocking Background File Import (std::sync::mpsc) & Live ProgressBar UI

Offloading board and session parsing onto a background worker thread (std::thread::spawn), streaming staged progress over an mpsc::channel, polling try_recv() without blocking the 60-FPS egui loop, and driving an egui::ProgressBar with ctx.request_repaint().

Why Synchronous File Parsing Freezes Immediate-Mode GUIs

In Lesson 0015, import_session_from_json ran synchronously on the main UI thread inside update(&mut self, ctx, frame). For a small 2 KB review envelope, that takes microseconds—but when an engineer opens a 50 MB industrial .kicad_pcb board file with 100,000 trace segments, synchronous parsing blocks update() for ratusan milliseconds, freezing panning, zooming, and OS window events.Never Block eframe::App::update: Because egui runs on a single UI thread, any operation taking more than ~4 ms should run on a background thread (std::thread::spawn) and communicate back via non-blocking message passing (std::sync::mpsc::Receiver::try_recv).

We keep the UI locked at 60 FPS with a three-part pattern:

  1. Spawn & Stream (spawn_background_session_import): Creates a std::sync::mpsc::channel::<ImportJobMessage>(), spawns a worker thread owning the raw JSON String (Send + 'static), emits staged ImportJobMessage::Progress updates ("Validating envelope", "Loading copper layers"), and finishes with Completed { board_id, board } or Failed(SessionIoError).
  2. Non-Blocking Poll (poll_async_import): At the start of each frame, drains available messages with while let Ok(msg) = rx.try_recv()—never blocking update()!
  3. Continuous Repaint & Cancellation (ctx.request_repaint()): In reactive desktop mode, egui sleeps when the mouse is idle. Calling ctx.request_repaint() while matches!(self.import_state, ImportJobState::Running { .. }) ensures update() keeps polling the channel until the worker finishes, and dropping self.import_rx = None cancels an in-flight job cleanly.
