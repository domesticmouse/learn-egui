Lesson 0004: Modeling Layers, Traces & Deterministic Z-Order

Structuring PCB geometry with enum PcbLayer, Vec<TraceSegment>, exhaustive match, and shared loop borrowing

In Lesson 0003, we transformed physical millimeter coordinates into screen space, but our traces were still individual hardcoded lines inside paint_board. Real KiCad boards contain thousands of segments across multiple layers that may appear in any order inside the file.

Because egui::Painter uses the classic painter's algorithm—every shape you emit is drawn directly on top of earlier shapes—drawing traces in arbitrary file order would cause a BottomCopper trace to paint right over a TopCopper pad or Silkscreen reference designator!

1. Exhaustive Layer Modeling with enum PcbLayer

Instead of scattering four separate boolean `if` blocks across our renderer, we represent a PCB layer as a Rust enum and attach pure methods using exhaustive match expressions:Because Rust's match is exhaustive at compile time, if you add an inner layer like PcbLayer::In1Cu later, rustc immediately flags every match block (`z_rank`, `color`, `is_layer_visible`) that needs updating. 

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum PcbLayer {
    BottomCopper,
    TopCopper,
    Silkscreen,
    Ratsnest,
}

impl PcbLayer {
    /// Deterministic back-to-front draw rank (0 = furthest back, 3 = topmost overlay).
    pub fn z_rank(self) -> u8 {
        match self {
            PcbLayer::BottomCopper => 0,
            PcbLayer::TopCopper => 1,
            PcbLayer::Silkscreen => 2,
            PcbLayer::Ratsnest => 3,
        }
    }

    pub fn color(self) -> Color32 {
        match self {
            PcbLayer::BottomCopper => Color32::from_rgb(59, 142, 234),
            PcbLayer::TopCopper => Color32::from_rgb(224, 82, 67),
            PcbLayer::Silkscreen => Color32::from_rgb(240, 230, 140),
            PcbLayer::Ratsnest => Color32::from_rgb(111, 247, 255),
        }
    }
}

2. Dynamic Collections (Vec<T>) & Shared Loop Borrowing

We store our board's segments in a growable heap vector Vec<TraceSegment> on PcbReviewerApp.Why write for seg in &self.traces (or self.traces.iter()) instead of for seg in self.traces? Iterating over a Vec by value moves and consumes the vector on Frame #1! Borrowing with & lets you read all segments 60 times a second while self.traces retains ownership. 

#[derive(Clone, Copy, Debug, PartialEq)]
pub struct TraceSegment {
    pub start: Pos2,
    pub end: Pos2,
    pub width_mm: f32,
    pub layer: PcbLayer,
}

impl PcbReviewerApp {
    pub fn is_layer_visible(&self, layer: PcbLayer) -> bool {
        match layer {
            PcbLayer::BottomCopper => self.show_bottom_copper,
            PcbLayer::TopCopper => self.show_top_copper,
            PcbLayer::Silkscreen => self.show_silkscreen,
            PcbLayer::Ratsnest => self.show_ratsnest,
        }
    }

    pub fn visible_traces_in_z_order(&self) -> Vec<TraceSegment> {
        let mut visible: Vec<TraceSegment> = self
            .traces
            .iter()
            .copied()
            .filter(|t| self.is_layer_visible(t.layer))
            .collect();
        visible.sort_by_key(|t| t.layer.z_rank());
        visible
    }
}

Interactive Lab 3: Eliminating Match-Arm Mutants cargo test + cargo mutants

One of cargo-mutants's superpowers is match-arm mutation: it tries replacing individual match arms or return values inside z_rank(), color(), and is_layer_visible(). By asserting each variant's exact rank, color, and visibility toggle in isolation, our 9 unit tests catch all 20 viable mutants! 

#[test]
fn visible_traces_in_z_order_filters_hidden_layers_and_sorts_back_to_front() {
    let mut app = PcbReviewerApp::default();
    // Input traces are deliberately stored in reverse (front-to-back) order:
    // Ratsnest (3) -> Silkscreen (2) -> TopCopper (1) -> BottomCopper (0)
    let default_visible = app.visible_traces_in_z_order();
    let default_layers: Vec<PcbLayer> = default_visible.iter().map(|t| t.layer).collect();
    assert_eq!(
        default_layers,
        vec![
            PcbLayer::BottomCopper,
            PcbLayer::TopCopper,
            PcbLayer::Silkscreen
        ]
    );
}
