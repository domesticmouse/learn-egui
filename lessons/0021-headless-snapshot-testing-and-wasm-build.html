Process-Wide GPU Serialization (gpu_lock) & Visual Snapshot Digests

When cargo test runs tests in parallel threads within a single OS process, spinning up multiple concurrent wgpu devices or offscreen snapshot renderers on Windows WARP, Mesa llvmpipe/RADV, or multi-ICD Vulkan drivers triggers driver-level access violations.Rule #1 of GPU & Snapshot Testing (egui-testing-infrastructure): Every test that touches a GPU device or captures an offscreen visual snapshot must acquire let _gpu = gpu_lock(); on its very first line. Using unwrap_or_else(std::sync::PoisonError::into_inner) keeps gpu_lock() 100% panic-free even if a prior test panicked while holding the guard.

Alongside gpu_lock(), we introduce FrameSnapshotDigest: a deterministic 64-bit FNV-1a digest of the active frame's visible layer bitmask (visible_layer_mask), visible culled pad count, visible culled trace count, and active DRC violation count. If any mutation flips a layer visibility bit, alters viewport culling, or suppresses DRC clearance markers, the frame's fnv1a_hash diverges immediately from the golden baseline!
