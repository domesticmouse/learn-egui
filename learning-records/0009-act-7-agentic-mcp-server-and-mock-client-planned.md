# Act VII (`0027`–`0030`): Agentic Hardware Review, `rmcp` Server & Mock MCP Client Workbench

The learner expanded the mission ([[MISSION.md]]) and curriculum roadmap ([[NOTES.md]]) with a dedicated seventh 4-lesson Act (`0027`–`0030`) focused on building a Model Context Protocol (MCP) server using the official Rust SDK (`rmcp` + `schemars`), while keeping the course open-ended for future acts beyond `0030`.

## Implications
- **LLM-Native Spatial & Electrical Queries (`0027`)**: Rather than merely wrapping generic CRUD commands, the engine must expose high-leverage queries that LLMs cannot reliably compute from raw KiCad S-expression text—spatial neighborhood radius lookups (`pcb.query_spatial_neighborhood`), net-topology summaries (`pcb.query_net_topology`), and parameterized custom DRC/decoupling checks (`pcb.run_custom_drc`).
- **Dual-Mode `rmcp` Server (`0028`–`0029`)**: Implement `PcbMcpServer` (`#[tool_router]`, `#[tool_handler]`, `kicad://` resources, and review prompts) supporting both **Headless Mode** (in-process `Session` over `stdio` or `tokio::io::duplex`) and **Bridged Live-GUI Mode** (authenticated loopback TCP control channel driving the live `egui` camera and returning cropped PNG board snapshots as `Content::image`).
- **Companion Mock MCP Client & Inspector Workbench (`0028`, `0030`)**: Build both a programmatic `rmcp` client test harness over `tokio::io::duplex` and an interactive `egui` **Mock MCP Client & Inspector Workbench** (with a `tools/list` schema explorer, live JSON-RPC frame log, inline image preview, and multi-step **Agent Review Playbooks**) to test Headless and Bridged modes under `cargo test` and `cargo mutants`.
